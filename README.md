# ⚡ ChatGPT Anti-Lag Archive

Userscript для Tampermonkey и Violentmonkey, который уменьшает нагрузку длинных чатов ChatGPT. Скрипт оставляет в живом DOM только несколько последних пар «пользователь → ассистент», а старые сообщения сохраняет локально в IndexedDB как статические HTML-снимки.

## Установка

1. Установите Tampermonkey или Violentmonkey.
2. Откройте [сырой файл userscript](https://raw.githubusercontent.com/modxhelp/chatgpt-anti-lag/main/chatgpt-anti-lag.user.js).
3. Подтвердите установку в менеджере userscript.
4. Перезагрузите страницу `https://chatgpt.com/`.

Версия 3.0.0 содержит `@updateURL` и `@downloadURL`, поэтому дальнейшие обновления могут устанавливаться средствами userscript-менеджера.

## Что делает версия 3.0.0

- Оставляет в DOM последние **6 пар** сообщений по умолчанию.
- Сохраняет каждое архивное сообщение отдельной записью IndexedDB.
- Не держит полный HTML всего архива постоянно в оперативной памяти.
- Восстанавливает локальный архив после перезагрузки страницы.
- Не записывает повторно уже сохранённые сообщения.
- Архивирует и восстанавливает сообщения небольшими пакетами.
- По возможности сохраняет целые пары «вопрос → ответ».
- Компенсирует изменение позиции прокрутки при удалении и восстановлении блоков.
- При ошибке записи или превышении квоты не удаляет исходное сообщение из DOM.
- Синхронизирует состояние нескольких вкладок через `BroadcastChannel` и Web Locks, когда браузер их поддерживает.
- Автоматически удаляет устаревшие архивы и контролирует занимаемый объём.
- Не отправляет переписку на сторонние серверы.

## Основные изменения относительно 2.0.0

В версии 2.0.0 весь архив чата хранился одной крупной записью и перезаписывался целиком. Кроме того, сохранённый архив очищался при повторной инициализации текущего чата. Версия 3.0.0 использует раздельные хранилища `chats` и `messages`, читает существующие метаданные при открытии чата и удаляет DOM-узел только после успешной фиксации записи.

Старое несовместимое хранилище версии 2.0.0 удаляется при обновлении схемы IndexedDB. Серверная история ChatGPT при этом не изменяется.

## Интерфейс

Панель `Anti-Lag 3.0.0` появляется в правом нижнем углу ChatGPT.

- **− / +** — количество последних пар, которые следует оставлять живыми.
- **Показать архив** — загружает ближайшую к живой части порцию статических снимков.
- **Ещё** — загружает следующую, более старую порцию.
- **Скрыть архив** — удаляет показанные снимки из DOM, но сохраняет их в IndexedDB.
- **Пересобрать чат** — очищает локальный архив текущего чата и перезагружает страницу.
- **Очистить всё** — удаляет все локальные архивы этого userscript в текущем профиле браузера.
- **Переключатель питания** — выключает архиватор, очищает локальный архив текущего чата и перезагружает страницу, чтобы вернуть оригинальные React-компоненты.

При увеличении количества живых пар уже удалённые оригинальные компоненты не могут быть восстановлены без перезагрузки страницы. Используйте **Пересобрать чат**, чтобы применить увеличенное значение ко всей переписке.

## Ограничения

Архивные сообщения — статические HTML-снимки. Текст, изображения и обычные ссылки обычно сохраняются, но React-состояние, обработчики кнопок, интерактивные виджеты, canvas и внутренние функции ChatGPT через `outerHTML` восстановить невозможно. Кнопки внутри снимков намеренно отключаются.

Для полноценного оригинального интерфейса используйте **Пересобрать чат** или выключите userscript. Селекторы ChatGPT могут измениться, поэтому после крупных обновлений интерфейса может потребоваться адаптация.

## Хранилище и лимиты

Настройки по умолчанию:

- архивирование — до 24 сообщений за проход;
- восстановление — до 20 сообщений за нажатие;
- максимум одного чата — 80 МБ;
- общий программный лимит — 150 МБ;
- максимум — 30 локальных архивов;
- срок хранения неактивного архива — 45 дней.

Фактическая квота IndexedDB определяется браузером и свободным местом на устройстве.

## Безопасность

Userscript работает только на `chatgpt.com` и `chat.openai.com`, не содержит `@require`, сетевых разрешений или запросов к сторонним сервисам.

Перед сохранением и повторной вставкой снимка удаляются:

- `script`, `iframe`, `object`, `embed`;
- `base` и перенаправляющие `meta`;
- inline-обработчики событий;
- `srcdoc`;
- ссылки и источники с протоколом `javascript:`.

## Проверка после установки

1. Откройте длинный сохранённый чат.
2. Убедитесь, что появилась панель `Anti-Lag 3.0.0`.
3. Проверьте, что в архиве появляются старые сообщения.
4. Перезагрузите страницу — число записей архива не должно удвоиться.
5. Нажмите **Показать архив**, затем **Ещё** и **Скрыть**.
6. Во время генерации ответа автоматическая архивация должна быть приостановлена.
7. Перейдите в другой чат и вернитесь назад — должен использоваться отдельный архив.
8. Проверьте **Пересобрать чат** на тестовой переписке.

## Разработка

Для проверки требуется Node.js 18 или новее:

```bash
npm run validate
```

Команда выполняет синтаксическую проверку userscript и статические проверки метаданных, безопасности и ключевых элементов реализации. Те же проверки запускаются через GitHub Actions при push в `main` и в pull request.
