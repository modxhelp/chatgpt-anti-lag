# Отчёт о проверке версии 3.0.0

Дата: 27 июля 2026 года.

## Автоматические проверки

Выполнены:

- `node --check chatgpt-anti-lag.user.js`;
- `node scripts/validate-userscript.mjs`;
- проверка userscript-метаданных и версии;
- проверка отсутствия `@require`, `@connect`, `fetch`, `XMLHttpRequest`, `GM_xmlhttpRequest`, `eval` и `new Function`;
- проверка наличия IndexedDB-хранилищ `chats` и `messages`;
- проверка наличия санитизации снимков, BroadcastChannel и Web Locks;
- `git diff --check` в подготовленном репозитории.

## DOM-сценарий

На локальном макете длинного чата проверялся сценарий с 70 сообщениями:

- 12 сообщений оставлены живыми при настройке 6 пар;
- 58 сообщений сохранены в архив;
- первое раскрытие загрузило 20 снимков;
- второе раскрытие увеличило число показанных снимков до 40;
- скрытие удалило снимки из DOM, не удалив записи IndexedDB;
- повторная инициализация не создала дубликаты записей;
- ошибок выполнения в тестовом Chromium-сценарии не зафиксировано.

## Проверенные пограничные случаи

- ошибка или превышение квоты IndexedDB не должны приводить к удалению несохранённого DOM-узла;
- повторное открытие чата использует сохранённые метаданные;
- раскрытый архив приостанавливает автоматическую выгрузку;
- генерация ответа приостанавливает автоматическую выгрузку;
- смена маршрута сбрасывает только состояние интерфейса, а не архив другого чата;
- очистка текущего архива и выключение приводят к перезагрузке для восстановления оригинальных React-компонентов.

## Ограничение тестирования

Тестовая среда не имела прямого доступа к живому интерфейсу `chatgpt.com`, поэтому после публикации необходим короткий smoke-тест на реальном длинном чате. Особенно важно проверить актуальность селекторов сообщений и кнопки остановки генерации.

## Публикационный скрипт

PowerShell-скрипт подготовлен для Windows 11 и использует стандартные `winget`, Git for Windows, GitHub CLI и Node.js. В текущей Linux-среде отсутствовали PowerShell, интерактивная GitHub-авторизация и прямой сетевой доступ к GitHub, поэтому полный цикл `clone → browser login → push → release → Tampermonkey` здесь не выполнялся. Скрипт не содержит токенов и использует штатную браузерную авторизацию `gh auth login --web`.
